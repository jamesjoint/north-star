Section 1: Data Model Redesign

The core change — splitting what's shared from what's per-user

Key Principle

Currently everything lives in one jobs table tied to you. The new model separates shared data (the job listings themselves) from user data (your scores, your tracker entries, your profile).

New Schema

Shared (all users)
jobs
  id, title, company
  location, remote, url
  source, description
  posted_at, fetched_at
  deleted

invites
  code, created_by_user_id
  used_by_user_id, expires_at
Per-user
users
  id, email, created_at

profiles
  user_id, background (JSON)
  dimensions (JSON), weights (JSON)

job_scores
  job_id, user_id
  score_aggregate
  score_dimensions (JSON)
  scored_at

boards
  id, user_id, name
  created_at

tracker_entries
  id, board_id, user_id, job_id
  status, notes
  follow_up_date, applied_date

What Changes in Practice

  • Scrapers write to jobs only — no user context needed
  • When a new user completes onboarding, their profile triggers background scoring of all current jobs → fills job_scores
  • New jobs added to the pool trigger scoring for all users who have a profile
  • Tracker status, notes, follow-up dates move from jobs to tracker_entries, scoped to a board
  • Your existing data migrates: your current jobs rows become the seed jobs pool + your job_scores + one default board with your current tracker entries
